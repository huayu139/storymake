# S6 对白演出 Director-Actor

## LLM 角色：导演 + 演员（IBSEN 式两层分离）

- **导演层**：给目标、阻碍、转折、信息边界——管剧情走向
- **演员层**：只知道自己知道的，用台词和动作演出来——管角色声音

两层分离的原因：不分离时所有角色都像作者一个人在说话。

## 输入

- episodes/eNN/cards.yaml（本集场景卡，合同——含 scene_ref/shot_size/camera/lighting/palette 与 scene_description/props/visual_beats）
- episodes/eNN 前一集的 state.yaml（知识状态）
- bible/characters/*.yaml（声音指纹 + 形象四件套）
- bible/scenes.yaml（场景锚点：空间基因/光线基调/固定色板，供 scene_ref 引用与色调核对）
- bible/world.md（空间与日常质感，写【场景】描述的依据）
- bible/voice.md（文风）
- visibility 规则（data-model.md 第 5 节）

## 生成流程（逐场进行，不许整集一次生成）

对每张场景卡：

### 第一步：导演层

产出 3 个节拍（beat），标注转折在第几拍：

```
节拍 1：（铺平衡）
节拍 2：（冲突升级 / 原策略失效）← 转折
节拍 3：（选择与代价）
```

同时输出本场的**信息注入清单**：每个角色本场允许知道什么。

### 第二步：演员层（每个角色一次，信息隔离）

给该角色的提示只包含：

- `knows + believes + suspects`（本场允许部分）
- `must_not_know` 作为硬约束明写："你绝不知道 X，任何台词不得暗示 X"
- 他的 voice_samples + voice_rules + never_say
- 本场目标（他想要什么，不给导演的全局意图）

输出格式：

```
【动作】（可拍的肢体行为，不写心理活动）
【台词】≤3 句，潜台词化，不解释自己为什么这么说
```

禁止：写心理活动、解释潜台词、旁白式说明。

### 第三步：组装

按卡片顺序把节拍与台词组装成 `episodes/eNN/script.md`：

```markdown
# 第 N 集剧本（暂定标题）

## 场景 1：地下库 · 夜
（林晚、顾彦辰）

【人物】林晚｜个性：信证据不信人，被噎住时反而更安静｜外表：28 岁，瘦，眼下有熬出来的青，指节有旧握笔茧｜穿着：男友风旧夹克，袖口磨白，口袋里那支录音笔露半截｜特征：撒谎前先摸一下耳垂，说真话时直视对方不眨眼

【场景】时间：深夜 ｜ 地点：小区地下车库 B2 层 ｜ 景别：中近景 ｜ 机位：固定 ｜ 光线：冷白灯管顶光，柔 ｜ 色调：水泥灰、冷白低饱和 ｜ 物件：行车记录仪、录音笔、车库门禁卡 ｜ 风格：冷白灯管下的空旷，回声比人声晚半拍
灯管嗡嗡响，只有她那辆车顶还积着一层灰。远处电梯口的指示灯是唯一的暖色，水泥地上留着两道新鲜的轮胎印。

【节拍 1】……

林晚：（靠在车边，没回头）你来得比我想的早。
顾彦辰：（把玩车钥匙）我怕有人比我更早。
……

（末场收尾 = 本集悬念，与 hooks.yaml 一致）
```

两行说明块的写法（QC 硬闸门 C10/C11）：

- **`【人物】` 行**：每个角色**本集首次出场**的那场写一次，之后不重复。
  格式 `【人物】显示名｜个性：…｜外表：…｜穿着：…｜特征：…`，内容与人物卡的
  `persona/appearance/wardrobe/signature` 一致（可压缩，不得改人物事实）。
- **`【场景】` 行**：每场必写，8 标签格式
  `【场景】时间：…｜地点：…｜景别：…｜机位：…｜光线：…｜色调：…｜物件：…｜风格：…`
  （景别/机位走枚举，光线含「光」+ 软硬词，色调 ≥4 字，值与场景卡一致），
  紧跟其后是 ≥30 字可拍描述（空间、陈设、光线、声音、气味、人流），
  来源是卡片的 `scene_description`，不得新编卡片之外的关键设定。
- 这两块是给美术、摄影、演员看的**说明**，不占表演时长（时长估算会自动扣除），
  但仍禁止心理活动、旁白与模糊词（`config/fuzzy-words.json`：氛围感/高级感/仿佛…）。
- 完整可粘贴的生图/生视频提示词不必手写：`scripts/prompt.py` 会自动拼装。

## 硬约束

1. **信息隔离**：台词中出现 must_not_know 内容 → blocker，必须重写
2. **声音指纹**：遮住名字要能认出说话人；三角色同场时句式必须拉开
3. **前 5 秒钩子**：本集第一行必须是冲突或异常，不许铺垫性开场
4. **末 5 秒悬念**：最后一句/动作必须留下 hooks.yaml 的 question_left_open
5. **价值落点**：本集结尾的价值状态必须等于 hooks.yaml 的 value_after
6. **潜台词**：角色不许说出自己的秘密、不许直接说明本场意图
7. **场景与人物可拍**：每场 `【场景】` 8 标签齐全且有 ≥30 字描述；每个角色本集首次出场有 `【人物】` 四要素行——缺项 `validate.py` 直接判 blocker，不得靠"读起来有画面"蒙混

## 用户决策点

逐场展示，用户可：改台词 / 换节拍顺序 / 只重写某角色的台词 / 整场重生成。

确认后写 script.md + 本集 `state.yaml`（集末人物状态、道具状态、知识状态增量、open_threads），
decisions.jsonl 留痕，`validate.py <slug> --stage script --episode N` → 请批准 → S7。

## state.yaml 的写法

每集结束时更新（详见 data-model.md）：

- 人物位置、伤势、持有物、关系变化
- knows/believes/suspects 增量（**从本集剧本中实际透露的内容提取，不许超写**）
- must_not_know 不变，除非本集正式揭露
- props 状态流转、open_threads

state.yaml 是下一集 S5/S6 的输入，也是连续性校验的依据。
